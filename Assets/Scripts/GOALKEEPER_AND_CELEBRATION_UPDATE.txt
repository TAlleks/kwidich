================================================================================
1. СИСТЕМА ПРАЗДНОВАНИЯ ГОЛОВ
================================================================================

НОВЫЕ ВОЗМОЖНОСТИ:
- После забитого гола забивший бот празднует 2.5 секунды
- Эффект празднования: вращение и подпрыгивание
- Все остальные боты замедляются во время празднования
- Мяч автоматически респавнится в центре поля
- Все боты возвращаются на стартовые позиции
- Игра продолжается после короткой паузы

ИЗМЕНЕННЫЕ ФАЙЛЫ:
- PlayerController.cs
  * Добавлен enum BotState (Normal, Celebrating, Returning)
  * Добавлены методы: StartCelebration(), UpdateCelebration(), StartReturning(), UpdateReturning(), ResetToNormal()
  * Сохранение стартовой позиции и ротации в Awake()
  * Обработка состояний в Update() и FixedUpdate()

- GameScoreManager.cs
  * Добавлена корутина HandleGoalSequence() для управления последовательностью после гола
  * Новые параметры: celebrationDuration, returnDuration, ballRespawnPosition
  * Метод AddGoal() теперь принимает AIPlayer scorer
  * Флаг isHandlingGoal предотвращает множественные вызовы

- GoalRing.cs
  * OnTriggerEnter() теперь находит забившего бота и передает его в GameScoreManager

- QuaffleController.cs
  * Добавлен метод RespawnAt(Vector3 position) для респавна в указанной позиции
  * Автоматическое снятие флага hasBall у владельца при респавне

НОВЫЕ ПАРАМЕТРЫ (настраиваются в Inspector):
- celebrationDuration (2.5 сек) - длительность празднования
- celebrationHeight (3m) - высота подпрыгивания
- celebrationSpinSpeed (360°/сек) - скорость вращения
- returnDuration (1.5 сек) - время на возврат
- ballRespawnPosition (Vector3.zero) - позиция респавна мяча

ПОСЛЕДОВАТЕЛЬНОСТЬ ПОСЛЕ ГОЛА:
1. Забивший бот начинает празднование (вращение + подпрыгивание)
2. Остальные боты замедляются
3. Ожидание 2.5 секунды
4. Проверка окончания игры (если счет достиг maxScore)
5. Респавн мяча в центре поля
6. Все боты возвращаются на стартовые позиции
7. Ожидание 1.5 секунды
8. Все боты возвращаются в нормальное состояние
9. Игра продолжается

================================================================================
2. СИСТЕМА ПЕРЕДАЧ ДЛЯ ВРАТАРЯ
================================================================================

НОВЫЕ ВОЗМОЖНОСТИ:
- Вратарь (Defender) теперь может передавать мяч открытым союзникам
- Умный поиск лучшего союзника для паса
- Проверка блокировки паса врагами
- Передача с упреждением (учитывает движение союзника)
- Приоритет передачи: Attacker > Support > другой Defender
- Если нет открытых союзников - вратарь пытается вынести мяч сам

ИЗМЕНЕННЫЕ ФАЙЛЫ:
- GameObjectManager.cs
  * Добавлен метод FindBestTeammateForPass() - поиск лучшего союзника для паса
  * Добавлен метод GetTeammates() - получение всех союзников команды
  * Оценка позиции союзника (ближе к воротам противника = лучше)
  * Бонусы для разных ролей (Attacker +0.3, Support +0.15)

- PlayerController.cs
  * Добавлен метод IsPassBlocked() - проверка блокировки паса врагами
  * Добавлен метод CalculatePassTarget() - расчет целевой позиции с упреждением
  * Добавлен метод PassToTeammate() - передача мяча союзнику
  * Изменен MakeDecision() - для Defender добавлена логика передач
  * Новое поле currentPassTarget - текущая цель для паса

НОВЫЕ ПАРАМЕТРЫ (настраиваются в Inspector):
- passRange (80m) - максимальная дистанция передачи
- passAccuracy (0.9) - точность передачи (0-1)
- passCheckRadius (5m) - радиус проверки блокировки
- passLeadTime (0.8 сек) - упреждение для движущихся целей
- passBlockLayer (LayerMask) - слой для проверки блокировки

ЛОГИКА РАБОТЫ:
1. Вратарь ловит мяч
2. Ищет лучшего союзника для паса (в пределах passRange)
3. Оценивает позицию союзника:
   - Чем ближе к воротам противника - тем лучше
   - Бонус для атакующих ролей
   - Штраф за слишком близкую дистанцию (<10m)
4. Проверяет, не заблокирован ли пас врагами (SphereCast)
5. Если пас открыт - передает мяч с упреждением
6. Если пас заблокирован - пытается вынести мяч сам

КРИТЕРИИ ВЫБОРА СОЮЗНИКА:
- Союзник должен быть в пределах passRange (80m)
- Приоритет: Attacker > Support > Defender
- Чем ближе к воротам противника - тем выше приоритет
- Не слишком близко к вратарю (минимум 10m)

3. ВИЗУАЛЬНЫЕ ЭФФЕКТЫ (GIZMOS)
================================================================================

НОВЫЕ ВИЗУАЛИЗАЦИИ:
- Линия передачи от вратаря к союзнику (зеленая = открыт, красная = заблокирован)
- Целевая позиция паса с упреждением (голубая сфера)
- Радиус проверки блокировки (оранжевая сфера)
- Индикатор состояния празднования (фиолетовая сфера над ботом)
- Линия возврата на стартовую позицию (белая линия)
- Стартовая позиция (белая сфера)

СУЩЕСТВУЮЩИЕ ВИЗУАЛИЗАЦИИ (для Defender):
- Домашние ворота (зеленая сфера)
- Граница поля (красные линии)
- Максимальная дистанция от ворот (синяя сфера)
- Зона предиктивного перехвата (желтая сфера)

4. НАСТРОЙКА В UNITY
================================================================================

ВАЖНО: После открытия проекта в Unity необходимо настроить:

1. GameScoreManager:
   - Установить ballRespawnPosition в центр поля (например, Vector3(0, 5, 0))
   - Настроить celebrationDuration и returnDuration по желанию

2. AIPlayer (для каждого бота):
   - Установить passBlockLayer (включить слои ботов и игрока)
   - Настроить passRange, passAccuracy, passCheckRadius по желанию
   - Убедиться, что у Defender правильно настроены defenderMaxDistance и defenderPredictionRange

3. Проверить стартовые позиции ботов:
   - Боты должны быть расставлены в нужных позициях в сцене
   - Эти позиции сохраняются автоматически в Awake()

7. ИСПРАВЛЕННЫЕ ОШИБКИ
================================================================================

v1.1 - Исправлена ошибка "Setting linear velocity of a kinematic body":
- ПРОБЛЕМА: В методе TryChangeOwner() пытались установить linearVelocity 
  ДО того, как сделали Rigidbody kinematic
- РЕШЕНИЕ: Изменен порядок операций - сначала rb.isKinematic = true, 
  затем rb.useGravity = false
- УЛУЧШЕНИЕ: Убрано ненужное обнуление velocity для kinematic тела 
  (kinematic тела игнорируют физику)

Файл: QuaffleController.cs, строки 104-112
Метод: TryChangeOwner()
